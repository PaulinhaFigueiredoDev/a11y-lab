Guia de navegação

Testes Web

Use o teclado para chegar aos controles, observar o foco e entender o que o leitor de tela anuncia.

Teclas principais

Tab
Avança para o próximo componente interativo.
Shift + Tab
Volta para o componente anterior.
Enter / Espaço
Ativa links, botões e controles.
Setas
Navegam dentro de tabs, menus e autocomplete.
Escape
Fecha diálogos, menus e sugestões abertas.
Home / End
Vão para o primeiro ou último item, quando aplicável.

Foco e leitor de tela

O foco deve ser visível, previsível e seguir uma ordem lógica. Confirme se o leitor anuncia nome, função, estado e mudança de conteúdo.

Quando um diálogo abrir, o foco deve entrar nele. Quando fechar, deve retornar ao controle que o abriu. O foco do navegador e a leitura do conteúdo devem permanecer coerentes, mesmo quando o leitor de tela estiver usando seu cursor de leitura.

Regra prática: Tab muda de componente; as setas geralmente movem o foco dentro de um componente complexo.

Guia de gestos

Testes mobile

Com VoiceOver ou TalkBack ativo, primeiro encontre o item e ouça seu anúncio; depois execute a ação.

iPhone + VoiceOver

  • Deslize para a direita ou esquerda para ir ao próximo ou item anterior.
  • Toque para selecionar e ouça nome, função e estado.
  • Toque duas vezes para ativar o controle selecionado.
  • Deslize com três dedos para rolar a página.
  • Use o Rotor para navegar por headings, links, botões e campos.

Android + TalkBack

  • Deslize para a direita ou esquerda para mover o foco entre itens.
  • Toque para explorar e ouvir o item sob o dedo.
  • Toque duas vezes para ativar o item focado.
  • Deslize com dois dedos para rolar a página.
  • Use os controles de leitura para navegar por headings, links, tabelas e campos.

Teste Web + áudio

Use o leitor.
Escute a interface.

Faça uma primeira passagem sem olhar para a tela. O objetivo é descobrir se a estrutura, os nomes e os estados são compreensíveis apenas pelo áudio.

NVDA + Chrome

  1. Abra o NVDA e recarregue a página.
  2. Use H para percorrer headings e D para landmarks.
  3. Use K para links e B para botões.
  4. Entre nos campos com Tab e confirme label, valor e erro.
  5. Teste os componentes e confirme se estados como “aberto”, “selecionado” e “fechado” são anunciados.
Guia WebAIM para testar com NVDA ↗

VoiceOver + Safari

  1. Ative o VoiceOver e navegue com VO + ← e VO + →.
  2. Use o Rotor para navegar por headings, links, botões e campos.
  3. Ative controles com VO + Espaço e confirme a mudança anunciada.
  4. Teste formulários, diálogos e mensagens sem depender da informação visual.
  5. Verifique se o foco entra e sai dos componentes sem perder o contexto.
Guia oficial do VoiceOver no Mac ↗

O que ouvir

  • Título da página e headings em ordem lógica.
  • Landmarks e nomes acessíveis dos controles.
  • Estado de tabs, menus, accordions e diálogo.
  • Labels, valores e mensagens de erro dos campos.
  • Mensagens dinâmicas, mudança de foco e retorno do foco.

    Ferramentas de apoio

    Lighthouse + axe
    como ponto de partida.

    Lighthouse

    No DevTools, abra Lighthouse, selecione Accessibility e gere um relatório em mobile ou desktop.

    axe

    Abra a extensão ou painel axe no DevTools e execute uma análise. Investigue cada resultado na interface.

    Depois do relatório

    Reproduza o problema com teclado e leitor de tela. A ferramenta ajuda, mas não substitui a validação manual.
